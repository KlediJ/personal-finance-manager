Libri security changes — 2026-10-30

Completed locally; no release was published and no real financial database was opened.

Runtime and dependencies
- Electron 45.1.0, better-sqlite3 13.0.3, maintained router and build tooling.
- Removed unused ONNX runtimes and the direct Lodash dependency. Active rule-based
  categorization and user feedback remain available. Unfinished electron/ai prototypes
  remain in source but are excluded from compilation and packaging.
- Patched compatible ExcelJS dependencies and legacy glob dependencies through
  documented package.json overrides. npm install reported zero vulnerabilities
  across the full 771-package audit, including development dependencies.
- package-lock.json is no longer ignored. Include it with the source changes.
- Use Node 22.15+ (tested with bundled Node 24.19.0; .node-version pins that version).
  The computer's default Node 20.16 is too old. .npmrc rejects incompatible installs.

Application boundaries
- Every production IPC handler checks the sender, top-level frame and exact app URL.
- Explicit renderer sandbox, content security policy, denied permissions, popups,
  remote navigation, redirects, webviews and automatic downloads.
- Imports/exports require a native-dialog grant bound to the originating window,
  selected path and extension. Export grants are single-use and revoked on cancellation.
- Import limits: 25 MB input, 50,000 rows and 200 columns; Excel ZIP validation bounds
  actual decompression to 100 MB and 10,000 entries before ExcelJS parses the workbook.
- CSV formula-looking text is escaped; numeric amounts retain their numeric values.

Data correctness and privacy
- Explicit US-style amount parsing preserves grouping and parentheses negatives;
  invalid or ambiguous formats are rejected instead of being partially parsed.
- Mixed regular/transfer import batches commit in one SQLite transaction or roll back.
  This prevents partial-import retries; it is not a full duplicate detection system.
- Removed automatic ingestion of developer CSVs from the working directory.
- Bank-training CSV remains on disk and is ignored; it is removed from the tracked
  tree in this development checkpoint. Older Git commits may still contain it; history and remote exposure need
  a separate review before any repository is made public. No history was rewritten.

- Fresh unsigned Windows directory build: work/security-package/win-unpacked.
- Package inspection found no nested archives/installers, CSVs, databases or ONNX

  This measures the archive, not a new compressed installer or Microsoft Store download.
- Existing dist release artifacts were retained; they are not the new secured release.

Validation
